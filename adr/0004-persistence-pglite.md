# ADR-0004: Embedded Postgres (PGlite) locally, Postgres when hosted

- Status: accepted
- Date: 2026-10-03

## Context

Krama runs on a developer's machine through `npx kramahq` and must also run hosted for teams. We need durable runs, decisions and events with optimistic concurrency, no compiler toolchain, and the same behaviour on Windows, Linux and macOS.

## Decision

Persist through a `Store` port. The default adapter uses **PGlite** (Postgres compiled to WASM) in a data directory owned by one process; hosted installs use **Postgres** through the same Drizzle schema. Entities are stored as `jsonb` documents with only filtered and sorted columns promoted. Migrations are generated by drizzle-kit and embedded in the bundle, so nothing is read from disk at start-up.

A one-day spike measured: durable restart, paths with spaces, transaction rollback, optimistic version checks, 500 sequential inserts in about 70 ms, a warm start of about 35 ms and a first start of under a second. The same contract suite passes on PGlite and Postgres 17 in CI.

## Consequences

- No native modules, so installs work without a compiler on every platform.
- One process owns a PGlite directory; running two servers on one data directory is unsupported.
- PGlite serialises queries on one connection, which is acceptable for a single-user local tool; hosted scale uses Postgres.
- If PGlite ever proves unreliable, the `Store` port allows a SQLite adapter without touching the engine.
